# FTX-1 原生 CW 接收解码设计

## 入口和屏幕

- 原厂 MODE 菜单中的现有 FT8 位置改为 `CUSTM`。点击后展开两个小按钮 `FT8` 和 `CW_DEC`。`FT8` 打开现有 FT8 页面。
- `CW_DEC` 回到主收信画面，在频谱下方、原厂软键上方停靠两行滚动文本。空间不足时缩短频谱下方的显示区域，为文本留出高度。频谱的调谐触控和原厂软键继续响应。具体边界以 3DSS、瀑布和 MULTI 的原厂绘制区域为准，待在模拟器里分别核实。
- 解码条显示译文、估计的接收 WPM 和关闭按钮。选中 `CW_DEC` 不改变 VFO 或收发模式。在 `CW-U` 或 `CW-L` 接收时运行，切到其他模式或本机发射时暂停。关闭、换台或切换边带时丢弃未完成的字符。

## 音频接入

首选复用 DISPLAY V01-10 上 FT8 已使用的接收 PCM 入口 `0x60445170`。现有挂钩先调用原厂帧处理，并按帧头样本数读取从偏移 4 开始的 16 位 PCM。已有 DATA-U 实机接收结果可作基线。CW-U 和 CW-L 下的采样率、音频通道、模式及收发状态的 DISPLAY 字段仍待验证，尤其要确认双接收时采到的是主接收机的音频。首版以主接收机当前调谐的一台为目标。

DMA 回调只交接有效样本和连续性信息。解码在后台任务处理，UI 线程按文本或状态变化刷新。发现丢帧就丢弃受影响的半个字符，避免把采样缺口当成电码间隔。本功能计划只在 DISPLAY 接收侧接入。

## 自动速度和音调跟踪

[Morse Expert 的公开规格](https://ve3nea.github.io/MorseExpert/)为 12–45 WPM、自动音调和 300–1100 Hz 的解码频段。以这个速度范围作为第一阶段的体验目标。实现可参照 [ggmorse 的音调、门限和速度估计](https://github.com/ggerganov/ggmorse/blob/master/src/ggmorse.cpp)，采用适合面板的固定缓冲 C 实现。

1. 优先在电台 CW PITCH 附近寻找符合键控节奏的窄带峰。读取不到面板的 PITCH 时，在约 300–1100 Hz 内搜索。对已锁定的音调做小范围跟踪，避免附近更强的连续载波或另一台抢走锁定。
2. 计算窄带能量包络，用噪声底和带迟滞的门限提取有声与无声区间。时间以 PCM 样本累计，允许一个 DMA 帧内连续处理多个短分析步。
3. 从短长有声段及字符内短间隔估计点长。初始化同时保留多种点长假设，直到收到了足够的节奏证据。锁定后用滑动统计跟踪缓慢变速，连续数个可信区间与当前估计冲突时重新捕获。以 [ITU-R M.1677-1](https://www.itu.int/rec/R-REC-M.1677-1-200910-I) 的点划和间隔比例作初值。单独估计字间和词间隔，使慢间隔练习及手键字距不会直接拉低字符速度。
4. 按字符持续输出，锁定不足时显示等待状态。CW-U 和 CW-L 都使用解调后的实数音频和同一解码器。[Yaesu 操作手册](https://www.yaesu.com/Files/4CB893D7-1018-01AF-FA97E9E9AD48B50C/FTX-1_OM_ENG_EH084M201_2506E-DS.pdf)确认 CW PITCH 调整的是接收 CW 音调及侧音。

## 容量和验证

FT8 发射台架版的 DISPLAY Stage 1 使用 10,364 / 10,970 B，Stage 2 使用 43,868 / 53,312 B。Stage 1 只剩 606 B，预留给入口分派和必要挂钩。CW 算法及停靠条绘制优先链接到 Stage 2，按最终 ELF 的段大小核算。运行态采用固定大小的队列、包络和字符缓冲，与 FT8 工作区按页面生命周期互斥。

验证顺序为本地 PCM 回放、面板模拟、再到实机接收。先用已知文本覆盖 12、20、30、45 WPM，以及一段录音内变速和加长字距。再用实录检查衰落、相邻电台、调谐换台、丢帧和本机侧音。记录锁定时间、速度误差、字符错误率和错台情况。面板模拟单独验证 `CUSTM` 的两个分支及停靠条对频谱、旋钮调谐和原厂软键的影响。实机确认 CW-U 与 CW-L 都有连续可解码的 PCM 后，再构建独立测试包。
