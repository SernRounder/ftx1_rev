# Gemini 实施提示词

把下一节整段发给 Gemini，并给它当前 `rev_ftx1` 工作区的完整源码快照。如果分多个对话工作，每次附上 [SSTV 交接文档](交接文档.md)、对应编号的短提示词和上一阶段交付，再使用相同基线。

## 主提示词

```text
你负责开发 Yaesu FTX-1 的机内 SSTV 功能。工作目录是 rev_ftx1。先读 docs/sstv/交接文档.md、outputs/ft8-cw-swr-fix/README.md、docs/development-handbook.md 和 patch 的实际源码。最终把实现与可复现证据交给 Codex 独立审计。

目标是保留当前联合版 FT8、CW_DEC、SWR SCAN 和原厂功能，首版增加 Robot 36 RX、逐行显示、完成图存 SD，以及从 SD 预读固定规格 BMP 后由用户明确发送一帧。接收和发射均用机内音频链。使用独立实验构建目录和输出，不覆盖现有 ft8-cw-swr-fix。首轮设备范围为 USB 和当前主接收机。DATA-U、更多 SSTV 模式和图片格式各自作为后续评估项。

基线是 DISPLAY V01-10 + MAIN V01-13 的 ft8-cw-swr-fix。按 docs/reproduce.md 核对原厂输入和输出 SHA-256，并记录当前 Git 提交。遇到历史交接中的菜单路径、协议或用量与当前构建不一致时，核对源码、SFL 与 ELF，留下差异记录。实现留在本仓库的 patch/。保留原厂恢复入口、更新器和保护区。

按以下顺序交付，可并行做好宿主编解码与资源论证。
0. 验证基线和工具链，记录可复现的命令与旧用例结果。
1. 先实现纯 C 流式 Robot 36 RX/TX，分别做 PySSTV→新 RX 及新 TX→独立 Robot36 解码器。验证 VIS、帧长、RGB/Y 色差顺序、像素时基、任意分块、行重同步、丢失/坏帧与第二帧。保存图像和 WAV，再记录独立工具版本与哈希。测试自己的编码和解码互通只能作为额外回归。
2. 单独交叉编译并量出算法和适配层 .text/.rodata/.data/.bss、栈、缓冲、DMA 与文件 I/O 峰值。当前联合 DISPLAY Stage 1 剩 66 B，Stage 2 剩 8 B。记录压缩重复代码、复用和候选代码洞的证据，保持启动搬运、应用槽及复位边界。没有安全的联合布局时，继续完成宿主与验证工作，提供可量化的资源阻塞报告和最小实验布局；扩大搬运边界、改引导或引入 SD 可执行代码另提方案。
3. 第一份设备方向的候选为 RX-only。复用现有 16 kHz 捕获链和 MAIN 模式同步路径，IRQ 仅做原有回调、边界校验及有限入队。worker 逐行译码，UI 交换前绘制，文件读写独立于实时环节。MENU 增设 SSTV 前核对功能 ID、动作码、标签区间、EEPROM 校验和原有配置。原厂 0x20 / 0x60 / 0x62 都跑真实解析与状态恢复，保留字节 34。验证 FT8/CW/SWR/SSTV 的互斥、迟到状态、双边沿 BACK、0x62 列表强制重绘及在途 DMA 归还。
4. 在宿主和 VM 中验证发送。图像校验和预览通过后才允许用户发一帧。逐块合成 PCM，复用原厂 TX 许可、DMA/缓存维护与整机状态。为 SSTV 另设有限租约，保留 FT8 的 13.5 秒上限，保护原厂 TOT、ALC、温度、SWR 和射频频段边界。SSTV 引导须等真实 KEYED，DMA 末块确认完成后才正常退回 RX。对 STOP/BACK、链路失联、音频欠载、频率/模式变化、过期或重复命令、外部 PTT、任务停滞和独立 MAIN 超时建立负向验证。证明哪条路径在 DISPLAY 或 MAIN 服务停滞时撤发，记录失败的触发到停发时间。
5. 运行联合回归与 SFL 回读。以明确的证据等级区分静态、宿主、VM、实机。未经另行授权不连接电台写入、刷机或做实机发射。RX-only 或收发实验包可留在本地并标明用途，给审计者提供同一次构建的 SFL、ELF、map、输入/输出哈希和原字节保护证据。没有通过的关口要落在交接记录里。

最终交给 Codex 的材料应包含实际基线指纹、源码改动、构建命令、第三方版本和许可证、同次构建的 SFL 与 ELF/map、RAM/栈/DMA 和代码区表，以及实际跑过的音频捕获入口和串口解析路径。同时提供独立互操作截图与 WAV、FT8/CW/SWR 回归和失败日志。标明每项结果来自宿主、仿真还是实机，列出用户仍需执行的台架项目。
```

## 分阶段短提示词

以下短提示词适用于分配给不同 Gemini 对话。把当前阶段的产出和汇总记录带到下一阶段。阶段 1 与阶段 2 可以独立推进，接入阶段共用同一协议和内存预算。

### 0　基线复现

> 只做基线复现和实验区准备。读取发布说明和交接文档，核对三份既有 SFL、对应 ELF、当前工作树及必要的未跟踪文件。以现有工具链重建同版本 DISPLAY 与原厂底包 MAIN，核对解包载荷与链接段。选取当前联合 UI、旧 TX/DMA 和更新器用例做基线回归。交付可复现命令、输入和输出哈希、依赖版本和既有失败项。保留现有发布镜像。

### 1　纯算法和独立互操作

> 实现 Robot 36 单模式纯 C RX/TX。输入接口接受 16 kHz、16-bit 单声道 PCM 分块，输出交稳定像素行给回调。发送接口按调用端请求逐块生成 PCM。先用外部编码与解码器建立独立样本。验证 VIS 模式码与奇偶校验、色差交替、首尾行、时基、噪声、频偏、采样漂移、缺块、截断和重新锁定。用可再生的色条、带边框图及两张连续图测试。交付源码、WAV/图像与哈希、依赖版本、实际时长与质量指标。把内存与计算成本量出来，保持接口可在裸机测试。

### 2　资源和硬件接入论证

> 用当前发布版 DISPLAY 和 MAIN 基线，测量最小 SSTV 目标的链接段。列出文件偏移和运行地址、保护区、各内存所有者、分配峰值、RTOS 栈和 DMA 对齐。逐项验证 16 kHz 当前音频入口、目标幅频范围、RGB565 和 SD BMP 路径。对静态联合版、独立 SSTV 实验目标和继续宿主工作的可行性列证据。给出可用的实际地址区间、原字节、无冲突依据和构建日志。若证据不足，完成测量和候选分析后转交审计。

### 3　机内 RX、菜单及保存

> 在资源证明范围内接入 SSTV 接收，通过真实 RX 挂钩喂 WAV，并实现 BUTTON SETUP 中的入口、逐行预览、完成／部分／失败状态和 BMP 保存。保留原有音频回调、页面、软键、输入路由与状态包的原厂字节。验证 FT8/CW/SWR 与 SSTV 的互斥，特别覆盖 SWR 退出时迟到的状态、BACK 按下与松开跨弹窗、0x62 列表恢复。用原厂 DISPLAY 调度器仿真交出一张图和一组 SD 错误复现。当前阶段的发射入口保持关闭。

### 4　机内 TX 与撤发

> 从已验证的 RX 模式、BMP、音频接口和资源布局出发，做 Robot 36 单帧发送的宿主和双端仿真。发送前预检并预读固定规格 BMP。收到 MAIN 键控确认后才发送 Leader。末块 DMA 确认完成后请求解键，收到真实 RX 确认且在途槽清空后归还工作区。用独立 SSTV 解码器验收整帧导出的 TX PCM。按交接文档逐项验证取消、超时、错误令牌、DMA 欠载、失联、任务停滞、换频／换模式和其他 PTT。记录每项故障的实际时间轨迹。保留 FT8 原租约、原厂发射限制、恢复入口和所有 PA 保护。此阶段只运行无 RF 的验证。

### 5　联合验收与材料整理

> 对候选源码和同次打包的 SFL/ELF/map 做独立回读。跑联合 UI、TX DMA、FT8 前后窗口、CW、SWR、MAIN 更新器以及原厂启动与调度回归。提交变更清单、镜像及原字节证据、互操作样本、正反向回归结果、剩余风险和实机台架方案。写清产物的适用范围和当前通过的关口，整理后交给 Codex。实机刷写和 RF 台架执行安排在审计之后。
