## 目标

在现有 FT8 接收实验镜像上:
1. 加入发射能力(消息编码 → 波形合成 → PTT → 音频提交)
2. 接收页面改为 WSJT-X 风格布局
3. 右下角固定"下一步发射内容"窗口: 标准通联消息(Tx1..Tx6)+ 自定义自由文本

## 范围

标准消息生成(依赖 MY/DX 呼号与格子)、自由文本输入 UI、模拟器全链验证

## 代码调研事实

- **编码链现成**: ft8_lib `ftx_message_encode`(文本→77bit, 自动识别标准/自由消息,
  自由文本上限 13 字符)、`ft8_encode`(→79 音符, 依赖 ldpc.c 生成矩阵——解码器尾部载荷已含 ldpc.c)、
  `synth_gfsk`(gen_ft8.c, GFSK 相位整形)。16kHz 下每符号 2560 采样, 波形总长 79×2560=202,240 采样=12.64s。
- **合成数学依赖**: erff/sinf/fmodf(libm)。对策: GFSK 脉冲表(3×2560 float≈30KB)Python 预生成嵌入尾部;
  sinf 用 LUT+插值自实现; 避免运行时 libm。
- **空间预算**: 空洞 10,976B 已用 7,064B(剩 ~3.9KB, 只够 UI 胶水);
  尾部 Stage2 现 25,612B, flash 余量 ~5.2MB → **编码器+合成器+波形状态机全部放尾部**, 尾部 ABI 升 v3。
- **发射链路**(work/an/report-display-tx-uart.md §1/§5, 高置信):
  - PTT: `E8 01 00 00 00 <mode> 00 00 00` 经 `FUN_00014a1c(buf,9)`; mode 1=TX on, 0=off。
    风险: 0x27ae0 监视逻辑可能 E8(0) 意外停止 → 要么完整走 0x27a8c(含状态字节 0x60936522), 要么绕开并确认监视不触发。
  - 音频: `FUN_0006b5f0(handle, pcm, 0)` 提交块(0xc80=800采样×2ch×16b @16kHz); handle 经 `FUN_00006ea8`(需 WAV 文件)
    或更底层 0x6a8f8/0x6995c。**最大不确定点**: E8 mode=1 时该流是否路由到 IFDSP 调制器——实机验证项。
  - 方案B备选: 预生成 WAV 放 SD 走原厂 voice-memory 全链(0x31424), 路由确定但时序抖动+SD 依赖。
- **时隙时基**: 设备无亚秒时钟(RTC 秒级+tick 插值, 未实现); RX 的 sync(sequence,skip) 目前由外部驱动。
  TX 调度必须复用同一时隙状态机。
- **现有可复用**: record_tx()(TX 历史记录)、ft8_locator(格子)、触摸分发钩子、距离计算、
  模拟器 Panel/LivePanel(可加 E8/音频块捕获桩)。
