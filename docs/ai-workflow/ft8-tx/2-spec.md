# FT8 发射 + WSJT-X 页面 + QSO 日志 — Spec(2-spec.md)

## Problem Statement

`ft8live-LAB.sfl` 已实现接收闭环(DMA 钩子→流式解码→双栏结果页),但无发射能力:
无消息编码、无 PTT 键控、无音频提交,页面也没有发射规划窗口。用户要求:
① 加入发射;② 页面按 WSJT-X 布局重排;③ 右下角固定"下一步发射内容"窗口,
支持标准通联消息(Tx1..Tx6)与自定义自由文本;④ 记录 QSO 日志到 SD 卡
(ADIF 兼容格式,方便上传 LoTW/eQSL/ClubLog),并在解码列表中标记已通联过的电台。
已拍板:路径 A(原始 E8+直写音频流)、手动触发、WSJT-X 忠实版布局、页内自绘迷你键盘。

## Solution(架构)

**总原则: 新代码一律进尾部 Stage2(余量 ~5MB),空洞 Stage1(剩 ~3.9KB)只加最小分发;
所有验证在 Unicorn 模拟器闭环,实机项归入既有 bring-up 清单。**

```
空洞 Stage1 (0x6052C670, 7,064B + ≤0.5B 分发)      尾部 Stage2 ft8_core (0x606C2FC0, 现 25.6KB)
┌────────────────────────────────┐                ┌──────────────────────────────────────┐
│ 钩子: mode_draw/hit/touch/      │                │ RX: open/begin/push_pcm/finish (现有) │
│       ui_worker/audio_capture   │   CORE 指针    │ TX(新): encode / tx_begin / tx_next   │
│ 事件分发 → core->hit/touch/draw │ ─────────────→ │ 消息模板: std_message(index,…)        │
│ (live 视图快照, 现有)            │                │ TX 引擎: arm/tick (E8+块提交+历史)     │
└────────────────────────────────┘                │ UI 绘制: 页面/键盘/NEXT TX (调原厂绘图) │
                                                  │ 合成: LUT 正弦+预生成 GFSK 脉冲表       │
                                                  └──────────────────────────────────────┘
```

- **编码链**(全在尾部): `ftx_message_encode`(文本→77bit,自动校验标准/自由格式,自由≤13字符)
  → `ft8_encode`(→79 音符; ldpc.c 已在尾部) → 流式 GFSK 合成 16kHz int16 单声道。
  数学: sinf 用 1024 点 LUT+线性插值自实现(-120dB 误差,FT8 足够); GFSK 脉冲表
  (3×2560 float≈30KB)由 Python 在构建期用 `math.erf` 预生成嵌入,运行时零 libm 依赖。
- **流式合成**: 每符号 2560 采样,总 79×2560=202,240 采样(12.64s)。`tx_next(state, buf, n)`
  增量产出,不驻留整个波形;状态机在 workspace(相位累加器+符号游标)。
- **PTT**: 调原厂 `FUN_00027a8c(mode)`(0x60427a8c, 1=开/0=关)——比裸 0x14a1c 多了
  TX 态字节 0x60936522 登记,降低被 0x27ae0 监视逻辑意外停止的风险。模拟器在
  0x14a1c 桩捕获帧断言 `E8 01 00 00 00 01/00 00 00 00`。
- **音频提交**: `FUN_0006b5f0(handle, pcm2ch, 0)`,800 采样×2ch×16bit 块(单声道复制为双声道),
  每 tick 提交一块。handle 获取(0x6ea8 WAV 或底层 0x6a8f8 族)与 DSP 路由=实机 bring-up 项,
  提交点隔离在 `submit_pcm()` 单函数,设备路径就绪前 handle 传 0(模拟器仍按调用捕获验证)。
- **TX 时序**: 手动 arm 后,在下一个时隙边界(RX 槽状态机 240,000 采样消费完的点,与 RX 共用
  同一时基)触发: E8(1) → 首块音频 → 每次 worker/poll tick 续块 → 202,240 采样完成 → E8(0)。
  E8 起振裕量靠首块前固定延迟块(0.3s 静音)对齐;发射期间 RX 照常消费帧(不解码有效信号,无害)。
- **时隙时钟显示**: 读原厂 RTC(0x135d4)秒值显示 HH:MM:SS(时区偏移为整分钟,15 整除 60,
  本地秒与 UTC 秒在时隙对齐上等价)。模拟器 stub 返回固定时间。

### UI(WSJT-X 忠实版, 800×480)

```
┌──────────────────────────────────┬─────────────────┐
│ MY GRID PM95uo        LOC 12:00:00│      BACK       │
├──────────────────────────────────┼─────────────────┤
│ BAND ACTIVITY (8行, 现有数据)      │ RX FREQUENCY    │
│  220 CQ F5RXL IN94    ~10267 km  │  K1ABC (大字)    │
│  440 K1JT HA0DU KN07  ~8949 km●  │  SNR --  FREQ 440│
│  ...点行=选DX, ●=已通联           ├─────────────────┤
│                                  │ NEXT TX (固定)   │
│  (键盘打开时覆盖左栏)              │ ▶Tx1 CQ N0CALL..│
│                                  │  Tx2..Tx6       │
│                                  │ FREE [___13__]⌨ │
│                                  │ [TX NEXT][STOP] │
│                                  │ [LOG] 已通联 12  │
└──────────────────────────────────┴─────────────────┘
```

- **消息模板**(尾部 `std_message`): Tx1 `CQ <MY> <GRID4>` / Tx2 `<DX> <MY> <GRID4>` /
  Tx3 `<DX> <MY> -08` / Tx4 `<DX> <MY> R-08` / Tx5 `<DX> <MY> RRR` / Tx6 `<DX> <MY> 73` /
  FREE 自由文本≤13 字符。报告值 v1 固定 -08(SNR 估计为后续项)。消息文本在选中时即时
  encode 验证,无效(呼号非法/缺 DX)置灰不可发。
- **DX 选中**: 点 Band Activity 行→启发式提取对方呼号(首个含数字的字母数字 token,跳过
  CQ/QRZ/DX 前缀,排除 MY)→填 DX + TX 音频频率取该行 frequency_hz(默认 1000 Hz)。
- **键盘**: 覆盖左栏,A-Z 0-9 SPACE BKSP ENTER(呼号字符集),用于 MY CALL/DX CALL/FREE
  三个输入框;调用序: 点输入框→键盘→ENTER 提交。BACK 在键盘打开时=收起键盘。
- **发射历史**: 现有 MY TRANSMISSIONS 面板移除,record_tx 保留,历史并入 NEXT TX 窗口
  底部状态行(最近一条已发消息)。
- **状态机显示**: NEXT TX 窗口显示 IDLE/ARMED(等待时隙)/TX(剩余秒)/DONE。

### QSO 日志(ADIF)与已通联标记

- **格式**: ADIF 2.x 文本(`.adi`),字段 `CALL / QSO_DATE / TIME_ON / TIME_OFF / MODE=FT8 /
  BAND / FREQ / GRIDSQUARE(对方, 解码行有则填) / STATION_CALLSIGN / MY_GRIDSQUARE /
  RST_SENT / RST_RCVD / <eor>`。LoTW/eQSL/ClubLog 可直接上传。
- **存储**: SD 卡单一文件 `I:\FTX-1\FT8LOG.ADI` 追加写(首条带头注释 `Generated by FTX-1 FT8`,
  每条记录 open-append-close,断电不丢已写记录)。文件不存在则创建。
- **写入时机(自动启发式 + 手动兜底, 用户已确认要自动)**:
  - 自动: ① 发送 Tx6(73)完成 → 立即记录;② 发送 Tx5(RRR)后,解码行出现当前 DX 发给
    本台且含 `73`/`RR73` → 记录。每 DX 每会话自动只记一次(去重);MY/DX/时间缺失则跳过。
  - 手动: [LOG] 按钮随时补记(自由文本通联、自动漏记场景),不受会话去重限制。
  报告取 Tx3/Tx4 模板值与解码行;无完整 QSO 状态机,启发式可能漏记(不误记:
    仅上述两个明确完成信号触发),漏记由手动兜底。
- **已通联标记**: bind 或 FT8 页首次进入时读 `FT8LOG.ADI` 解析全部 `<CALL:n>` 入 RAM 集合
  (上限 512 呼号 ×13B, 超出保留最近);Band Activity 行中对方呼号命中集合 → 行尾 ● 标记
  (绿色);本会话 LOG 后立即更新集合与标记。计数显示于 [LOG] 按钮旁。
- **RF 频率来源**: 优先解析无线电状态镜像 0x60935bb4 的 BCD 频率字段(执行期 RE 切片,
  候选偏移由 0x20-0x33 命令应用函数 xref 定位);RE 失败或字段无效 → 构建期默认 `--freq`
  (如 14.074,同时推 BAND=20m)。FREQ = RF + 音频偏移/1e6。
- **文件 API**: 执行期 RE 定位原厂 open/read/write/close 原语(录音写 WAV 证明其存在,
  线索 0x74ec/0x6ea8/0x829c);路径字符串编码(ASCII/UTF-16)以 RE 结论为准。
  全部调用隔离在 `log_open/log_write/log_close` 单点;模拟器以桩捕获写字节流断言 ADIF 内容,
  读侧桩回放固定 ADIF 样本验证解析与标记。

### ABI 变更

尾部 `ft8_arm_api` v2→v3(头部偏移不变, 尾部追加):
```c
int      (*encode)(const char *text, uint8_t tones[79]);          /* 1=可编码 */
void     (*tx_begin)(struct ft8_tx *, const uint8_t *tones, uint32_t hz);
size_t   (*tx_next)(struct ft8_tx *, int16_t *pcm, size_t max);   /* 0=完成 */
int      (*std_message)(unsigned index, char out[35]);            /* 0=不可用 */
int      (*tx_arm)(const char *text, uint32_t hz);                /* 1=已武装 */
unsigned (*tx_tick)(void);                                        /* 返回状态 */
int      (*ui_hit)(int pressed, u32 x, u32 y);                    /* 页内目标 */
void     (*ui_draw)(void *frame);                                 /* 页面绘制 */
int      (*set_calls)(const char *my, const char *dx);
int      (*log_qso)(void);                       /* 1=已追加 ADIF 记录 */
int      (*worked_before)(const char *call);     /* 1=已通联 */
```
live ABI `ft8_live_api` v3→v4 同步追加;`struct workspace` 扩展(设置串/TX 状态/UI 状态),
bind 重初始化;emu 侧 LivePanel 从新 ABI 表驱动,旧测试按新版本号更新。

## User Stories

1. 操作者在 FT8 页点一条解码行 → RX FREQUENCY 面板显示对方呼号,NEXT TX 的 Tx2-6
   由灰变亮(模板已可编码)。
2. 操作者点 FREE 行 → 迷你键盘输入 ≤13 字符 → ENTER → 该文本成为待发消息。
3. 操作者选 Tx1(或任一有效项)→ 点 TX NEXT → 状态 ARMED,下一时隙边界自动
   发出 E8(1)+12.64s 音频+E8(0),历史行显示已发内容。
4. 模拟器里: 测试脚本武装发射后驱动时隙,捕获的 E8 帧与音频块拼接回灌解码器,
   解出的消息与待发文本一致(自发自收回环)。
5. 操作者发送 RRR 后收到对方 73(或本台发完 73)→ SD 卡 `FT8LOG.ADI` 自动追加一条含
   呼号/时间/频率/格子/报告的 ADIF 记录,文件可被 LoTW/ClubLog 直接接受;此后该电台在
   解码列表行尾显示 ● 已通联标记(含从既有日志读出的历史呼号);特殊场景点 [LOG] 手动补记。
6. 模拟器里: 读桩回放含 3 条呼号的 ADIF 样本 → 3 个呼号被标记;LOG 后写桩捕获的
   字节流经主机 ADIF 校验器(字段齐全、日期时间来自 RTC 桩、<eor> 闭合)。

## Implementation Decisions

1. 新代码全进尾部;空洞新增仅事件分发几行 — 保护 10,976B 上限不击穿。
2. 合成数学直接用 musl libm(sinf/erff)—— 执行期发现尾部载荷本就以
   `arm-linux-musleabihf` + `-lm` 构建(kiss_fft 已用 sinf/cosf),原"零 libm 需 LUT"
   前提不成立;GFSK 脉冲在 tx_start 时一次计算(7680 次 erff)存入状态,不做构建期表。
3. PTT 走 0x27a8c(mode) 而非裸帧 — 保留原厂状态登记,风险更低。
4. 音频提交/句柄获取隔离单点 — 实机路由是 bring-up 独立项,不阻塞模拟器验证。
5. TX 与 RX 共用时隙状态机 — 单一时基,设备侧将来只需一个独立任务。
6. 报告固定 -08、无 SNR 估计、无自动应答 — 显式 v1 界限。
7. 尾部 ABI 版本 2→3、live ABI 3→4,旧载荷新内核(或反之)拒绝加载 — 前后向安全。
8. QSO 记录 = 自动启发式(发 73 完成或发 RRR 后收到 73/RR73,每 DX 每会话一次)
   + [LOG] 手动兜底;已通联判定只按呼号(不分 band/mode);按频段区分 = v2。
9. ADIF 单文件追加,记录级 open-close — 断电安全、实现最小。
10. 文件 I/O 与 RF 频率读取各自隔离单点,RE 结论只影响单点实现 — 不确定性不扩散。

## Out of Scope

- 实机 bring-up(E8 语境有效性、音频路由、handle、worker tick 节拍、尾区加载、SD 实卡读写)——
  沿用 RX 实机四步清单,不因 TX/日志扩大模拟器侧工作。
- 自动应答序列、SNR 估计报告、呼号/文本持久化(内存+日志文件除外)、
  FT4、双流(收发同时异频)、按频段/模式的已通联区分、Cabrillo 格式
  (自动记录仅上述两个明确完成信号的启发式,非完整 QSO 状态机)。
- MAIN/IFDSP 侧任何改动;不触碰原厂自身 QSO log 功能。
