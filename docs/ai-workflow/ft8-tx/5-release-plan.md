# FT8 实机放行状态

已按用户指定的台架首刷范围交付 DISPLAY 原生接收候选。完整收发仍在开发。

- 文件为 `outputs/ft8-bench-rx/FTX-1_DISPLAY_V0110.SFL`，2,937,852 字节。SHA-256 为 `654f7800a8b5eccd47d0d03a9f1f06e9dba2b0edafd3dba884a65a045d7f9783`。
- 通过 SFL 校验、解包比对和原厂调度器中的菜单打开与退出测试。整机录音回放仍未通过。原生键控禁用，界面显示 `TX OFFLINE`。
- 用户实机确认首刷可启动并进入 FT8，反馈原厂 MODE 弹窗会很快关闭，且可听到信号时没有解码结果。
- 第二版文件为 `outputs/ft8-bench-rx2/FTX-1_DISPLAY_V0110.SFL`，2,938,204 字节。SHA-256 为 `08b0e3f750453e08d26ff1c604e3520884506857bfa8876e2c447763facaadf5`。屏幕从原厂 MODE 弹窗状态脱离，接收使用重叠窗口。已验证弹窗关闭后能保持工作并用 BACK 退出，偏移 7.3 秒的录音在 ARM 测试中解出四条已知消息。
- 第二版在原厂调度器下回放录音，捕获入口、解码任务和结果发布串联解出了三条已知消息。模拟器从 PCM 捕获入口注入数据，尚不覆盖真实 SPI DMA。
- 用户实机报告第二版 `RX 10` 后 `SKIP` 持续增加，页面一直等待。模拟持续的优先级 7 负载复现旧版 `RX 10 / OUT 0`，把解码任务优先级由 8 调至 6 后，同一测试进出队均为 24 帧。
- 第三版文件为 `outputs/ft8-bench-rx3/FTX-1_DISPLAY_V0110.SFL`，2,937,108 字节。SHA-256 为 `fb50fefe237f3bd5b2cdb49e6741a6c2b707a6a658fa200565d7b018c00b0f41`。
- 第三版实机照片显示 `RX 1008 / OUT 1008 / SKIP 16 / SCAN 3`，并处于重新积累音频的状态。第四版保留最近一次成功的解码行，短时队列溢出按丢失的采样数填入静音，`DROP` 排除零长度帧。
- 第四版文件为 `outputs/ft8-bench-rx4/FTX-1_DISPLAY_V0110.SFL`，2,937,988 字节。SHA-256 为 `570b0821f546b0441a1535ded15a5fb5f60c379fcc75ebab07606cd14bc3745a`。

- 旧版实验镜像（SHA-256 前缀 `0aa9cf51c2be4158`）存在未释放 PTT 的风险，退出后也可能保留排队发射。
- 更新后的 `ft8live-LAB` 用于本地模拟，原厂接收任务和发射适配器尚未接入。
- 同长度菜单候选和诊断候选用于开发。首刷候选按原厂升级菜单选择 DISPLAY 更新。设备无法进入更新菜单时的恢复尚未验证。
