# FTX‑1 自定义快捷菜单改造计划

固件已回滚到原厂底栏。下文保留两次快捷栏试验的设计和实现记录。

## 目标与参考

把主屏频谱下方的六个软键变成可配置的原厂菜单快捷入口。每格显示菜单项名称与当前值，点按直接进入该项的调节界面。

当前设计采用单页六格。长按 `FUNC` 打开的是 `PAGE 1/3 SSB`、`PAGE 2/3 CW`、`PAGE 3/3 FM/C4FM` 的功能菜单。「自定义快捷键」可从这三页的全部功能项和设置入口为第 1–6 格跨页选配，也可留空。`PAGE/BACK/FWD` 属于菜单导航。保存后返回频谱主屏，取消时保留上次保存的排列。`MODE → CUSTM` 继续作为 FT8/CW 的入口。快捷栏的绘制和命中只覆盖原厂底栏，CW 的三行译文仍在其上方，FT8 页面使用自己的软键。菜单目录见 [Yaesu 操作手册印刷页 22–23](https://www.yaesu.com/Files/4CB893D7-1018-01AF-FA97E9E9AD48B50C/FTX-1_OM_ENG_EH084M201_2506E-DS.pdf)。

### 六格布局与实机接入

- DISPLAY V0110 已确认原厂底栏六个触区从 `y=420` 开始，各为 `133×60`。绘制与命中共用槽位表，只在频谱主屏上接管这六格。原厂菜单、键盘和其它模态页拥有自己的绘制与触摸。参见[固件逆向入口](analysis.md)。
- 槽位保存稳定的菜单项 ID，显示名称和当前值在进入主屏与值变化时从原厂状态读取。为每项保留原厂行为：如 `BK-IN` 为切换，`CW PITCH` 和 `DIMMER` 为调节，设置分类项进入对应子菜单。可选范围与当前能否操作分开，当前模式或配件不适用时置灰。逐项核对触发手势、VFO 归属和一次触摸只执行一次。
- 保存的是六格的顺序。跨关机存储可使用已验证的配置接口或独立 SD 卡配置；文件缺失或损坏时回退到原厂底栏。

### DISPLAY V0110 三页测试版

- `SHORTCUTS` 的 `BAR` 切换正在编辑的底栏页，点选五格之一后，用 `LST` 浏览三页 57 个功能项。`SAVE` 应用 15 格布局，`CANCEL` 放弃。主屏第一格 `PAGE` 循环切换三个底栏页。
- 点击快捷键后，DISPLAY 发送原厂 FUNC 长按事件，等收到 `0x37` 页面后通过原厂 BACK/FWD 导航。到达目标页后，复用该项的短按/松手事件，并沿用原厂页面回报的禁用状态。底栏只显示名称，调节值由原厂页面显示。
- 配置保存在 SD 卡的 `FTX-1/SOFTKEY.BIN`。文件格式从 `0x51` 改为 `0x52`，旧版六格记录按原厂底栏处理，进入编辑器保存后启用三页布局。构建启用 `--shortcuts`，关闭 `--profile`。

### DISPLAY V0110 旧版六格实现

- 长按 `FUNC` 后进入 `SHORTCUTS`，逐格点击选择 `D-MODE`、`3DSS`、`MULTI`、`SCOPE`、`SPAN`、`SPEED` 或留空。`SAVE` 保存并请求返回主屏，`CANCEL` 丢弃本次编辑。固件复用原厂底栏的状态数据和触摸事件，其他候选项仍需核对原厂调节入口。
- 有 SD 卡时，保存写入 `FTX-1/SOFTKEY.BIN`，启动时恢复。读不到有效记录时使用原厂布局。写卡失败时，本次开机内仍可应用编辑结果。
- 使用 `--radio --tx-hooks --custom-modes --vfp-only --cw-debounce --shortcuts` 生成联合镜像。本版 Stage 1 为 10,964 / 10,970 字节，Stage 2 为 53,300 / 53,312 字节。快捷栏另外使用四段已核对的应用区空隙，由链接脚本检查边界。

## 开发顺序

| 阶段 | 改造 | 验收 |
| --- | --- | --- |
| 1. 确定原厂接入点 | 从 `D-MODE`、`SCOPE` 等现有标签追到主屏底栏的绘制、命中和事件分发，核对单／双 VFO 下的参数来源。用固定六格验证绘制与原厂底栏恢复。 | 画面与触区同位。进出 MODE 或设置、按 BACK 后无残影或失效触区。 |
| 2. 接通快捷动作 | 用静态表描述菜单项 ID、标签、当前值、适用条件和事件入口。先逐项核对 `DNR`、`NB`、`AGC` 等原厂菜单项。原厂动作走现有菜单流程，值从原厂状态读回。 | 用原厂菜单和快捷栏分别操作，参数和值双向一致。切换 VFO 和模式后，禁用项、参数归属以及触摸动作正确。 |
| 3. 加入槽位编辑 | 在长按 `FUNC` 打开的菜单里增加「自定义快捷键」。三页功能项和设置入口都能分配给任意槽位，支持留空。验证配置读写路径后再启用跨开机保存。 | 保存后排列生效，取消保留原排列。冷启动恢复布局，未知 ID 或损坏配置回退到原厂底栏。 |
| 4. 联调和实机包 | 在联合构建里验证原厂键盘、FUNC 菜单、FT8 和 CW 共存。先出 DISPLAY 测试包。`TUNE`、`ANT` 等依赖配件和发射状态的快捷项，在状态与原厂入口验证后加入。 | 模拟检查重叠触区和按下／松开各触发一次。实机检查冷启动、主屏多种布局、旋钮调整、快捷页恢复和现有 FT8/CW 入口。 |


## 改动边界和容量

目前 `CUSTM` 是 MODE 弹窗里的两个固定坐标按钮，已验证其触摸路由和原厂弹窗恢复，可复用入口和测试方法。主屏底栏是另一处界面，先定位它自己的绘制与事件入口。键盘、原厂菜单和全屏 FT8 打开时，由当前界面处理触摸。底栏绘制和命中共用同一份槽位布局，状态变化时局部刷新。 [现有 CUSTM 代码](../patch/payload/cw_panel.c#L119) · [联合模拟测试](../patch/test_custom_modes.py)

以现有无软件增益联合构建为参照，Stage 1 为 10,884 / 10,970 字节，Stage 2 链接段为 53,136 / 53,312 字节。菜单编辑与持久化的整体体积尚需实测。第一阶段记录同配置构建的段大小和打包后终点，超限时先检查是否能复用原厂绘制和收敛现有重复代码，再决定是否调整布局。首版以现有启动搬运边界、可脱离 SD 卡运行、DISPLAY 单独更新为目标。 [链接布局](../patch/payload/ft8_radio.ld) · [打包上限](../patch/merge_display.py#L22)
