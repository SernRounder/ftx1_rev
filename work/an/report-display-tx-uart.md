# FTX-1 DISPLAY 固件逆向报告: 发射音频→PTT 链路 / 面板↔MAIN 串口协议 / 时钟 / 固件布局

对象: `work/dec/display/display.bin` (2,895,804 = 0x2C2FBC 字节, 版本 V01-10, 日期 2026/07/09, `FTX-1_DISPLAY_V0110.SFL`)
**运行基址: 0x60400000 (SDRAM)**。本文所有 `0x0000xxxx` 形式的地址 = 文件偏移; 运行时地址 = `0x60400000 + 文件偏移`(证据见 §4)。Ghidra 工程按基址 0 分析,代码全部位置无关,反编译结果不受影响,但换算绝对地址时必须 +0x60400000。

## 1. 【PTT 链路】语音存储发射如何让 MAIN 键控 PTT

### 结论(高置信)
面板向 MAIN 发送 **协议命令 0xE8 (语音发射请求)** / **0xE7 (信标·数据发射请求)**,两个都是 9 字节定长消息,经命令引擎组帧后从 SCIF5 发给 MAIN,由 MAIN 键控 PTT。**PTT 不是 GPIO,不走 RSPI,就是串口协议命令。**

### 完整调用链(文件偏移)

| 地址 | 函数 | 作用 |
|---|---|---|
| 0x00027a8c | FUN_00027a8c(mode) | **构造 0xE8 语音 TX 请求并发送**。报文模板在栈上拼 12 字节(发送 9 字节): `E8 01 00 00 00 <mode> 00 00 00`,置全局 TX 态字节 0x60936522 = {1,0},然后 `FUN_00014a1c(&msg, 9)`。mode: **0=TX off, 1=voice-memory TX on, 2=录音(TX on)**(调用点实证: 0x315a4 用 1, 0x31604 录音用 2, 0x316cc/0x27d54 停止用 0) |
| 0x00027a30 | FUN_00027a30(mode) | 同型 **0xE7 信标 TX 请求**: `E7 01 00 00 00 <mode> 00 00 00`,置 0x60936522={1,0x7f}。调用者 FUN_00041724/FUN_00041ff8 = APRS 信标控制器(QSOAPRSBCN 文件) |
| 0x00031424 | FUN_00031424(cmd) | 语音存储播放/录音 UI 入口。播放发射分支: 先 `FUN_00027a8c(1)`(请求 PTT)→ `FUN_00007670(name,2)`(启动播放); 录音分支: `FUN_00027a8c(2)` → `FUN_000074ec(...)`; 停止: `FUN_00027a8c(0)` |
| 0x00027ae0 | FUN_00027ae0 | 发射条件监视/停止序列(带内检查 FUN_00025838 → 频段存储槽 0xa3;条件失败→ E8(0) 停止) |
| 0x00007670 | FUN_00007670(name,ch) | voice-memory 播放启动: 拷贝 16 字节文件名,置 ctx+3=声道、ctx+0x24=1,`set_flg(ctx->flag, 4)`唤醒录音放音控制器 |
| 0x000074ec | FUN_000074ec(...) | 录音启动(生成 `I:\FTX-1\MESSAGE\%c%c%c.%c%c%c.%c%c%c` 文件名,`set_flg(flag, 2)`) |
| 0x0000829c | FUN_0000829c | 语音录放控制器任务(已知)。收事件标志位: bit1(2)=录音、bit2(4)=播放、bit3(8)=停止、bit4(0x10)、bit5(0x20) |
| 0x00007c7c | FUN_00007c7c(blk) | 播放 PCM 块提交: 检查 0x607c0078 bit6(总就绪门,FUN_00005798)→ `FUN_0006b5f0(ctx+0x30 句柄, blk+0x5c, 0)` |
| 0x0006b5f0→0x0006b57c→0x00068a88 | 音频流写 | 0x6b5f0 取锁(0x76e50/0x76e84); 0x68a88 为通用块流写(块池 0x724c8 分配、0x6cf70/0x6d020 写设备)——语音句柄的 sink 即 DSP 板方向音频队列(与已知事实一致,RSPI 驱动 0x0af0-0x2600,任务名 `spi_slave_task`@0x2bf830) |

### 发射时序(推断,中高置信)
1. UI 触发 → `FUN_00027a8c(1)`: 0xE8 消息入命令引擎 pending 槽(0x608af076, 9 字节, flag[8]),等待发送;
2. 命令引擎(cmd_interval/retry 任务,见 §2)组帧发 `AA .. E8 01 00 00 00 01 00 00 00 <sum>`,等 MAIN 的 ACK(0x06);
3. `FUN_00007670` 置播放标志,0x829c 任务打开 WAV(FUN_00006ea8)、按 0xc80 字节块回读 PCM、`FUN_00007c7c`→音频流→DSP 板调制发射;期间 0x27ae0/0x31424 轮询状态(FUN_000073a0 读 ctx+0x1c 状态机值: 4=播放中, 0x10/0x20=结束, 8=暂停);
4. 结束 → `FUN_00027a8c(0)` 释放 PTT。

### 0xE8/0xE7 报文字节图
```
偏移:  0    1    2    3    4    5    6    7    8
      +----+----+----+----+----+----+----+----+
      | E8 | 01 | 00 | 00 | 00 | MD | 00 | 00 |   MD=0: TX off
      +----+----+----+----+----+----+----+----+   MD=1: 语音存储 TX on
                                                    MD=2: 录音(TX on)
E7 同型, MD=1 为信标/数据 TX on(0x60936522[1]=0x7f 区分)
(字节 5 位置来自反编译 CONCAT11(param_1,(char)DAT_00027ad8), DAT_00027ad8=0)
```

## 2. 【面板↔MAIN 协议】SCIF5, 345600bps

### 物理层(高置信,证据充分)
- **UART = SCIF5, 基址 0xE8009800**(RZ/A1H 第 6 个 SCIF,Linux `ttySC5` 同址;固件 literal 0x1cff0/0x1cffc/0x1d008)。
- 寄存器布局(4 字节间隔,SH/RZ 风格): SCSMR+0x00(16b), SCBRR+0x04(8b), SCSCR+0x08, SCFSR+0x10, SCFTDR+0x0C(TX), SCFRDR+0x14(RX,0x1d008 literal=0xE8009814), SCFCR+0x18, SCFDR+0x1C, SCLSR+0x24, SCEMR+0x28。
- **串口参数字符串 `345600 B8 PN S2`**(0x15824): 345600bps、8 数据位、无校验、2 停止位。波特率特例表: 345600→BRR 0x16, 9600(0x2580)→BRR 0xCF;计算常数 P=66,600,010Hz(0x1cff8)。
- 支持软件流控 XON(0x11)/XOFF(0x13)(RX ISR 内处理)。
- SCIF5 引脚复用: 0xfcfef800+2 |= 0xC00(FUN_000131fc)。
- 驱动栈:
  - 0x1c964 波特率初始化; 0x1c910 ctx(0x608c0ac4)与环形 FIFO 初始化(TX 环 0x608c1b3c..0x608c2b3c 共 0x1000B,RX 环 0x608c0b3c 起 0x1000B);
  - 0x1cc6c **RX ISR**(读 SCFSR/清 0xFF6F,错误位 0x1C,SCFRDR→ctx+3,SCFDR 排空,SCLSR 溢出检查,XON/XOFF);
  - 0x1cadc 单字节入 TX 环 + `SCSCR |= 0x80`(TIE,空中断排空); 0x1cbe4 从 RX 环取字节;
  - 0x1d184/0x1d250 = svc 串口读/写系统调用处理(阻塞时建信号量等待);0x1c834(读)/0x1c894(写)为端口多路复用(端口表 0x604d2460, 0x1C 字节/项, read@+8 write@+0x10);
  - 0x1ce94 串口选项解析(`PE`/`PO`/`S2`/`B7`/`XON`/波特率十进制);
  - IRQ 注册 FUN_00016468(id,handler),0xF1-0xF4(0x1d0f4 处默认化;实际 ISR 经内核 IRQ 表)。

### 帧格式

**面板→MAIN**(FUN_0001464c 组帧,高置信):
```
字节:  AA  00 | LL  LL | <payload …> | SUM
       ↑同步0xAA | ↑u16LE 长度 = payload字节数+1(含SUM)
       payload = 命令字节 + 数据
       SUM = payload 全部字节之和(不含 AA/LEN/SUM 自身), 单字节截断
例: E8 TX-on → AA 00 0A 00 E8 01 00 00 00 01 00 00 00 EA
    ACK      → AA 00 05 00 06 00 00 00 00 06
    NAK      → AA 00 05 00 15 <err> <cmd> 00 00 <sum>
```
(缓冲区前 4 字节为 µITRON 消息头,不上线;0xAA 在 buf+4。)

**MAIN→面板**(FUN_000c9858/0xc9bf4/0xc932c 解析,高置信):
```
<cmd> <data…> SUM        ← 无 AA/LEN 头!
cmd 必须在 53 项命令表(0x607c02f8, 每项 0xC 字节 {cmd, u16 size@+2, flag@+4, rxcount@+8})内
size = cmd 后数据长度; 校验 SUM = 前 (size+1) 字节之和, 位于 buf[size+1]
收到 → 逐命令合法性校验(FUN_000c932c) → ACK(FUN_000c9b04) → 分发(FUN_000c965c)
```

### 命令引擎(面板→MAIN 方向)

## 3. 【时钟】时间来源与同步路径

### 结论(机制高置信;个别 RAM 细节中置信)
1. **面板有自己的本地 RTC 芯片**(显示板上的串行总线 RTC,非 RZ/A1H 内部),走 FUN_000133xx 总线驱动(控制器 ctx ≈ 0x606c02e0 一带,位 banged/控制器寄存器):
   - **FUN_000135d4 = 读时间**: 发命令 **0xA6**,连读 **7 字节 BCD**(年,月,日,星期,h,m,s);
   - FUN_00013514 = 写时间(命令 **0x26**); FUN_000134a0 = 写单寄存器(命令 = 索引|6);
   - FUN_00013884 = BCD→二进制结构 `{[0]=s,[1]=m,[2]=h,[3]=day,[4]=month-1,[5]=year+100→20xx}`;被 FUN_00076f14(µITRON 系统时间)调用。
   - RTC 芯片型号未确认(0xA6/0x26 命令风格接近 RX-8025NB/RX8900 系列,中置信)。
2. **MAIN 通过协议命令 0x65 向面板推送日期时间**(Y/M/D/h/m 5 字段;字段布局见 §2 表)。GPS NMEA($GPRMC/$GPGGA)在 MAIN 解析(已知),**面板不见 NMEA**;"GPS TIME SET"的结果经 0x65 下发,面板侧应用函数(未完全定位,位于 Ghidra 未识别区 0xc6000-0xcd800 的状态应用任务)将其写入本地 RTC(FUN_00013738 一族写 RTC 包装无静态调用者,疑经 0x65 应用路径调用——中置信)。
3. 面板 UI 修改时钟: FUN_00041990/FUN_00043b20(TIME SET 菜单)→ FUN_000137dc → 写 RTC。
4. 开机时 FUN_00015fc8(主初始化)调用 FUN_000139a4(经 FUN_000134a0 写 RTC 单寄存器,疑为使能/校准)。

### 对 FT8 15 秒时隙的意义
- 时隙同步可用的秒级时源 = RTC 读 FUN_000135d4/FUN_00013884(秒在返回结构 [0])。**无亚秒信息**——需要用内核节拍(dly_tsk/OSTM,FUN_000132b0 读 (0x604d?ctx)+4 的 tick)插值,或监测 0x65 推送沿。
- 0x65 是否周期推送未确证(可能仅变化时推送);若仅变化推送,长期精度依赖面板 RTC 晶体(典型 ±20ppm → 15s 槽 0.3ms,够用)。

## 4. 【DISPLAY 固件布局】加载基址 / 启动流 / 可注入空间

### 运行基址 = 0x60400000(高置信,三条独立证据)
1. **复位自举**(0x0-0x1f 为 B 指令式向量表,PIC): `0x2c mov r0,#0xD3; msr cpsr_c` → SVC; `0x34 ldr sp,[0x28]` = **0x606dc000**(初始栈,SDRAM)→ cache/MMU init → `0x48 mov r4,pc` 探测当前地址; `r0=[0x1FC]=0x60400050`; `subs r0,r0,r4; beq 0xe4`——**若不在链接地址 0x6040000x,则把镜像头 0x2B40 字节拷到 0x60400000 并跳 0x60400080**(在 SDRAM 副本中继续)。→ 链接基址 0x60400000,常态下整个镜像在复位前已被拷贝到 0x60400000(由 RZ/A1H boot ROM 按 SPI 启动配置完成——中高置信;boot 配置区在串行 flash 内,不在本镜像)。
2. **µITRON 任务结构表**(文件 0xd1220-0xd1500): T_CTSK{…, entry@+8, priority=3, stack=0x100, name@+0x14};entry 值全部 = 0x60400000+文件偏移。例: 0xd12e8 = entry 0x604145f0(= 文件 0x145f0,即 `uart` 任务,name 指针 0xd12f8 → 0x2bf87c = "uart")。任务表节选: `key`=0x12d6c, `powon`≈0x13158, `GPS`=0x131b0, `uart`=0x145f0, `cmd_interval`=0x156ac, `retry`=0x154cc, 主初始化=0x15fc8, ISR 表 0x17384-0x1810c+。
3. **VBAR = 0x60400000**(0xe4 路径: `0xf8 ldr r0,[0x21C]=0x60400000; mcr p15,0,r0,c12,c0,0`),各模式栈 0x604164f0/0x604bf54c/0x604bf614;MMU 恒等映射(0x2cc0 建 4096×1MB 平坦页表,0x2ce4 开 MMU/ICache/DCache);BSS 清零/数据拷贝目标 [0x606c02e0, 0x606cffff]。

### 内存布局总图(推断)
```
0x00000000-0x001FFFFF  串行 flash 直接访问区(RZ/A1H SPI boot)—— .SFL 镜像源
0x60400000-0x606C2FBC  镜像(=0x60400000+文件偏移): 代码+只读+静态初始化数据
0x606C2FBC-…           内核 BSS/数据(0x606c02e0 起),运行期堆
0x604d1xxx(镜像内文件0xd1xxx…)  注意: 文件 0xd1000-0xd2000 为静态任务/同步对象结构区(非代码)
0x606dc000             初始/SVC 栈
0x607c0000-0x607c0800  全局状态窗(touch 0x607c0058-78, 音频ctx 0x607c0090, 协议ctx 0x607c02b8…)
0x608af006-0x609xxxxx  协议 pending 缓冲/无线电状态镜像 0x60935bb4(~0x300B)/内核对象池 0x608bf7c8…
外设: SCIF5 0xE8009800, RSPI 0x3fefa000/0x3fefb000, CPG/STBC 0xfcfe0xxx, PIOR 0xfcfef800, L2C(PL310) 0x3FFFF000-0x3FFFFFFF
```

### 0x3fffff80 真相(修正任务提示)
0x1453c/0x15ca8 两处 literal **0x3fffff80 不是高向量**,而是 **PL310 L2 cache 控制器 Power Control 寄存器**(0x15c00: `ldr r0,=0x3fffff80; str r1,[r0]` 写 1 开启动态时钟门控;同函数还写 0xfcfe01b0/0xfcfe01b4 等待机时钟寄存器)。0x14510 池(0x3fefb000+0xfcfe0420-0444+0x3fffff80)属于时钟/存储控制器初始化代码。**高向量已禁用**(SCTLR bit13 V=0),向量经 VBAR=0x60400000 重定位。摘要文件所记"向量表 @0x2C70"实为 MMU/cache 初始化代码(0x2c84 起)前的数据池(0xFEE9/0x3FF/0x7FFF/页表描述子 0x84188380/0x00C50078),非向量表。

### 可注入空白区(镜像内,随启动自动进 RAM,可直接执行;共 3 处 ≥1KB 的 0xFF 连续块)
| # | 文件偏移 | 长度 | 运行时地址 | 备注 |
|---|---|---|---|---|
| 1 | **0x12c66c-0x12f14a** | **10,976B** | 0x6052C66C-0x6052F14A | 字形/字体数据区中的空洞(前后均为 UTF-16 字形表),首选 |
| 2 | 0x2ba2ca-0x2bae00 | 2,870B | 0x606BA2CA-0x606BAE00 | 尾部更新 UI 字符串区附近 |
| 3 | 0x1e5d3a-0x1e65f2 | 2,232B | 0x605E5D3A-0x605E65F2 | 词索引表之间 |

- 镜像内无 ≥512B 的 0x00 连续块(零页都在 RAM BSS)。
- **镜像尾 0x2c2fbc 之后**的串行 flash 余量: 镜像头(`.SFL` 文本头)声明 PC=2,896,380(=镜像长),未声明 flash 总容量;若显示板 flash 为 8MB(0x800000),则 0x2c2fbc 后约 **5.2MB** 未用——但启动时仅拷贝镜像长度,尾区代码不会自动映射,需经 SPI multi-I/O 控制器(0xfcfe0420-0444,初始化代码在 0x144xx/0x15bxx 一带)或 RSPI1(0x3fefb000)手动读入,或修改 boot 配置的拷贝长度(未定位,中置信)。**建议优先用镜像内空白区**。

## 5. FT8 发射复用 voice-memory 通路的改动点判断

复用程度从高到低三档:

### 方案 A(推荐): 协议 PTT + 直写音频流
1. **键控**: 直接构造 E8 报文 `E8 01 00 00 00 01 00 00 00` 调 `FUN_00014a1c(buf,9)`(运行时地址 0x60414a1c)。比走 FUN_00027a8c 更干净(后者还改 0x60936522 状态字节,若不模拟 UI 状态机可能被 0x27ae0 的监视逻辑 E8(0) 意外停止——**必须二选一: 要么完整走 0x27a8c+状态标志,要么绕开且确认 0x27ae0 的触发条件不满足**)。
2. **音频**: 语音句柄的底层提交是 `FUN_0006b5f0(handle, pcm, 0)`(0x6046b5f0)。需要:
   - 打开一个音频输出流获得 handle(FUN_00006ea8 需要真实 WAV 文件;更底层 = FUN_0006a8f8/FUN_0006995c 打开 + FUN_0006b318/0x69758 族配置,0x604xxxxx;可先用一个预生成的 16kHz/2ch WAV 占位文件走通 FUN_00006ea8,再在 0x829c 播放环外自驱);
   - 按 0xc80(3200B=800 采样×2ch×16b)或更小的块,把 FT8 合成 PCM(16kHz 单音 8-FSK,上行 12.6s)双声道复制后循环提交;块节奏参考 0x829c 中 `FUN_00007b78`(缓冲水位 8000B 上限,块步进 0xc80)。
   - **注意**: 实测需要确认该音频流在"发射"时是否路由到 IFDSP 调制器(voice TX 场景下应该是;0xE8 的 mode 可能决定 DSP 路由,这是方案的最大不确定点)。
3. **时序**: E8 发出后等 MAIN 实际起振(状态帧回读,或固定延时 100-300ms),再起音频流;结束发 `E8 … 00`。时隙对齐用 RTC 秒(FUN_000135d4)+ 内核 tick 插值。

### 方案 B: 完全伪装成 voice-memory 播放
预生成 FT8 WAV 放 `I:\FTX-1\MESSAGE\`,复用 FUN_00031424/0x7670/0x27a8c 全链(含状态机)。改动最少,但 15s 时隙对齐受文件打开/回读延迟抖动影响,且每次发射需 SD 卡文件。

### 方案 C: 绕过面板音频,由 IFDSP 直接发(不推荐)
需逆向 DSP 板 RSPI 协议(0x0af0-0x2600, `spi_slave_task`),工作量另计。

### 注入与挂钩
- 代码放 0x12c66c(运行时 0x6052C66C,10.7KB 够 FT8 音频合成+协议封装;若含接收解码则需扩到尾区或方案 B 文件);
- 挂钩点建议: ①周期任务(`cmd_interval` 0x156ac 或 0x25 号 cyclic,天然 10ms 级节拍,可做时隙状态机);②或 UI 键扫描任务 `key`(0x12d6c)注入触发键;③直接 patch FUN_00027a8c 入口跳转做 A/B 切换。
- 绝对地址换算: 运行时 = 0x60400000 + 文件偏移。

## 附: 置信度汇总
- E8/E7 为 TX/PTT 请求、消息布局、发送链路: **高**(调用点+字节模板+pending 槽三方印证)
- SCIF5/345600 8N2、帧格式(AA/LEN/SUM; RX 无头定长表): **高**
- MAIN→面板命令语义(0x20-0x7F 族): **中**(校验逻辑推断,未逐一动态验证)
- 0x65=时间推送、面板 RTC(0xA6/0x26): **高**(字段校验+BCD 转换+年+2000 实证);0x65 写回 RTC 的具体应用函数: **中**
- 基址 0x60400000、VBAR、启动流: **高**(三条独立静态证据);boot ROM 整体拷贝: **中高**
- 尾部 flash 余量 5.2MB(8MB 假设): **中**(未从镜像证实 flash 容量)
